## 一、目標

讓風自然 10～30 位員工每月自行排休假，送出後可互相看到大家的休假；主管再據此編排早、晚班的最終班表，並自動標示「職務代理人組別」內同天休假的情況。手機與電腦網頁都能使用，頁面可列印與匯出。

### 硬性約束（最高優先）
**整個專案不得覆蓋或影響任何其他專案。** 具體落地方式見第十一節「零影響其他專案」。

## 二、角色與權限

| 角色 | 權限 |
|---|---|
| 員工（`staff`） | 登入、排自己的休假、存草稿、送出、送出後修改並重新送出；送出後看全員休假；看最終班表；看到所屬代理人組別的紅色警示 |
| 主管（`manager`） | 具備員工全部權限；管理員工帳號（新增／停用／重設密碼）；班別設定；代理人組別設定；編排最終班表（可調整任何人）；月份管理；查看每人最後修改時間；匯出與列印 |

角色以 Firebase Auth **客製化 claim `shiftRole`** 表示（`manager` / `staff`）。**不使用既有 `role` claim**，避免影響其他 App 的 admin 判定。

## 三、帳號與登入

- 重用 `opencode-sk` 既有的 **Firebase Auth（Email/密碼）** 使用者池。
- 員工帳號 = `主管輸入的前綴` + 固定後綴 `@shift.local`（後綴固定、英文，例：`wang@shift.local`）。
- 首次登入：帳號帶 `mustChangePassword=true` 時，強制導向改密碼頁。
- 密碼政策：≥8 碼、含英文字母與數字（沿用既有後台規則）。
- 主管重設密碼：由 Cloud Function 設定臨時密碼並勾 `mustChangePassword`（`@shift.local` 無真實信箱，不用寄信重設）。
- **主管帳號管理只允許操作 email 結尾為 `@shift.local` 的帳號**，其他帳號一律拒絕。
- 首次主管帳號：用一次性 setup token（比照既有 `create-setup-token.js` 模式）於網頁 `/setup` 建立；token 用後即失效。

## 四、資料模型（Firestore，集合一律 `shift_` 開頭）

| 集合／文件 | 欄位 |
|---|---|
| `shift_users/{uid}` | `name`, `loginPrefix`, `shiftRole`, `active`, `mustChangePassword`, `createdAt`, `updatedAt` |
| `shift_shiftTypes/{id}` | `name`, `startTime`, `endTime`, `color`, `active`, `order` |
| `shift_agentGroups/{id}` | `name`, `memberUids: []`, `active`, `order` |
| `shift_months/{ym}`（`ym`=`YYYY-MM`） | `status`: `closed`\|`open`\|`arranging`, `deadline`(Timestamp\|null), `holidayDays`(自動計算), `quotaOverride`(Number\|null), `updatedAt` |
| `shift_leaves/{ym}_{uid}` | `uid`, `ym`, `dates: ["YYYY-MM-DD"]`, `status`: `draft`\|`submitted`, `submittedAt`, `updatedAt`, `updatedBy` |
| `shift_finals/{ym}` | `days: { "YYYY-MM-DD": { [uid]: shiftId \| "REST" } }`, `updatedAt`, `updatedBy` |
| `shift_settings/app` | `weekendRule`: `{ enabled, friMax:1, satMax:1, sunMax:1 }` |
| 國定假日 | 內建 `data/holidays.js`（近兩年政府行事曆；未含則空），主管可逐月覆寫 `quotaOverride` |

「最後修改時間／修改人」直接記錄於 `shift_leaves` 與 `shift_finals` 的 `updatedAt` / `updatedBy`，只保留最近一筆。

### localStorage
一律使用前綴 `shift_`（例：`shift_lastViewedMonth`）。

## 五、核心流程

### 月份生命週期
```
closed（未開放） --主管開啟--> open（開放排休） --主管切換--> arranging（編排中）
```
- `closed`：員工不可排該月。
- `open`：員工可排／送／改。
- `arranging`：主管編排中，員工仍可看。

### 員工休假狀態機
```
draft（草稿） --送出--> submitted（已送出） --修改--> draft --重新送出--> submitted
```
- `submitted` 後，其他員工才看得到；未送出者對別人顯示「尚未送出」。

### 截止日（軟提醒）
- 過截止日僅顯示橘色「已過排休截止日」，**不阻擋**送出或修改。

### 最終班表
- 主管在員工休假基礎上，為每人每天指派「班別」或「休（`REST`）」。
- 所有人班表可重複編排；員工**免發布**即時看到。

### 員工改休 vs 主管已編
- 保留主管既有編排；若某員工重新送出休假，主管端在該員工當月標示「休假已更新，請確認」。

## 六、警示邏輯

### 紅色警示（代理人衝突）
- 規則：同一 `shift_agentGroups` 組內、同一天 ≥ 2 人休 → 該日紅。
- 「全員休假總覽」依**員工 `submitted` 的休**判定。
- 「最終班表」依**主管指派的 `REST`** 判定。
- 各自即時重算（`onSnapshot`）；顯示日期與同時休假的人員；**只提醒不阻擋**。

### 橘色警示（軟性規則提醒）
- 週末：每人每月 週五／週六／週日**各別**超過 `friMax`/`satMax`/`sunMax`（預設各 1）。
- 總量：當月休假總天數 > 「可休假日」。
- 「可休假日」預設 = 該月國定紅字假日天數（依內建行事曆），主管可覆寫（`quotaOverride`）；畫面上方顯示「本月可休 X 天」。

### 優先序
同時存在時，紅色優先顯示。

## 九、技術架構

- **前端**：vanilla HTML / CSS / JS＋Firebase Web SDK（modular），無框架，與 workspace 慣例一致；純邏輯抽成可測試模組。
- **即時**：Firestore `onSnapshot`（休假、最終班表、代理人組別、月份）。
- **後端（Admin 操作）**：本專案專屬 Cloud Function。
  - 檔案：`functions/index.js`（Express app），`exports.shiftApi = ...`
  - 路由：
    - `POST /api/shift/setup`（一次性 token，建立首位主管）
    - `POST /api/shift/employees`（新增員工）
    - `PUT /api/shift/employees/:uid`（改姓名／啟停用／角色）
    - `PUT /api/shift/employees/:uid/reset-password`
    - `DELETE /api/shift/employees/:uid`
  - 每條路由：`verifyIdToken` 並檢查 `shiftRole === 'manager'`，且目標 email 必須以 `@shift.local` 結尾。
- **Firestore 規則**：先備份線上規則 → 只**追加** `shift_*` 段落 → 走漂移檢查。規則原則：
  - `shift_users` / `shift_shiftTypes` / `shift_agentGroups` / `shift_months` / `shift_finals` / `shift_settings`：登入者可讀；寫入僅主管（`shiftRole == 'manager'`）。
  - `shift_leaves`：登入者可讀；寫入僅限本人文件。
- **Hosting site**：`fzshift-sk`（新 site）。
- **部署**：`npm run deploy:safe`（含 `tools/check-rules-drift.js --strict`）。函式部署僅用 `firebase deploy --only functions:shiftApi`。

## 十一、零影響其他專案（硬性）

1. **獨立 git repo**：於 `風自然班表/` 執行 `git init`，不 commit 進父層 `firebase雲端資料夾` repo。
2. **獨立 Hosting site**：`fzshift-sk`，`firebase.json` 明列 `"site": "fzshift-sk"`；只部署此 target。
3. **Firestore**：
   - 只**新增** `shift_*` 集合，不讀寫、不刪除任何既有集合。
   - 動 `firestore.rules` 前先 `node tools/check-rules-drift.js`（先備份），只追加 `shift_*`，**嚴禁覆蓋**既有段落。
   - 一律走 `npm run deploy:safe`，不直接 `firebase deploy --only firestore`。
4. **Cloud Functions**：
   - 使用獨立 `codebase: "shift"` 與函式名 `shiftApi`，與既有 `api`（codebase `default`）完全分離。
   - 部署僅指定 `--only functions:shiftApi`，部署後驗證既有 `api` 仍在。
5. **Auth**：只建立／修改 `@shift.local` 帳號；不動任何其他帳號；不使用既有 `role` claim。
6. **不修改**父層或其他專案的任何檔案、`.firebaserc`、設定或資料。
